# brief.json — ТЗ заказчика в машинном виде

Один файл описывает, **что** нужно заказчику. **Где** что стоит, решает движок. Любое поле можно пропустить: тогда берётся умолчание из таблицы, а отчёт скрипта пишет, какое допущение сделано.

## Содержание
1. Поля и умолчания
2. Как читать опросник (строка опросника → поле)
3. Спорные случаи
4. Пример

## 1. Поля и умолчания

| Поле | Значения | Умолчание | Что делает |
|---|---|---|---|
| `name` | строка | — | ЖК / компания, попадает в название плана |
| `building.area` | м² | — | площадь помещения; нужна она или `w`+`d` |
| `building.w`, `building.d` | м | подбираются | длина вдоль витража и глубина. Если их нет, скрипт пробует 3 типичные глубины и берёт лучшую |
| `building.h` | м | 4,5 | высота потолка; «6–7 м» → 6,5 (середина, но ≥ 6,2, чтобы влезла антресоль) |
| `building.upper` | `auto` \| `mezz` \| `none` | `auto` | второй уровень: `auto` = антресоль при h ≥ 6,2 м (≈ 20 % площади, туда уходит служебное) |
| `sales.managers` | число | 4 | мест продаж (МПП, хантеры); РОП сюда **не** входит |
| `sales.format` | `open` \| `glass` | `glass` | открытые столы в зале или кабинеты со стеклом |
| `meet` | `{n, seats}` / число / false | нет | переговорные; `seats` 4 / 6 / 8 / 10 / 12 определяет комнату и стол |
| `vip` | число | 0 | сделочные / VIP, 16–20 м² |
| `bank` | число | 0 | места банка / ипотеки |
| `cashier` | true/false | false | касса (в Узбекистане часто нужна) |
| `director` | `room` \| `backoffice` \| false | нет | кабинет РОП 4×4 или место в бэк-офисе |
| `backoffice` | число сотрудников | 0 | бэк-офис, 6 м² на место |
| `reception` | 0 / 1 / 2 / 3 | 1 | сколько человек за стойкой; 0 — без ресепшен |
| `waiting` | мест | max(6; 1,5·M) | зона ожидания, 1,8 м² на место |
| `cafe` | `bar` \| `corner` \| false | нет | бар с бариста (5×3,2) или кофе-уголок |
| `kids` | `corner` \| `room` \| false | нет | детский уголок в зале или комната со стеклом |
| `maket` | `6x5` `6x4` `5x3` `3x2` `2x1.5` \| `screen` \| false | по площади | стол макета (зона = стол + обход 1 м) |
| `media` | true/false | false | медиа / VR / большой экран |
| `showroom` | `samples` \| `mockup` \| false | нет | образцы (4,5×3,2) или мокап (7,5×3,2) |
| `wardrobe` | `rack` \| `room` \| false | нет | гардероб гостей |
| `wc_guest` | `one` \| `mf` | `mf` от 380 м² | один универсальный с/у (МГН) или М + Ж + МГН |
| `wc_staff` | число | 0 | отдельные с/у персонала (0 — общий с гостями) |
| `kitchen` | `{seats, type: table\|mini}` / false | по штату | кухня персонала; до 200 м² — мини |
| `archive`, `storage`, `prayer`, `server` | true/false | server — с 220 м² | архив / склад POS / комната для намаза / серверная |
| `security` | `street` \| `desk` \| `room` | — | `room` ставит помещение, иначе только примечание |
| `optional` | список ключей | [] | что заказчик пометил «если останется место»: это убирается **первым** |
| `notes` | строка | — | всё, что не ложится в поля (стиль, цвета, пожелания) |

Всегда закладываются, даже без отметки: тамбур (от 150 м²), КУИ, электрощитовая, с/у гостей.

## 2. Как читать опросник

`read_brief.py` показывает отмеченное как `[✔ …]`. Если в строке отмечено «нет», помещение не нужно. Нет отметки ни «да», ни «нет» — берите умолчание и допишите его в список допущений в ответе.

| Строка опросника | Поле |
|---|---|
| Площадь помещения / Размеры / Высота | `building.area`, `w`×`d`, `h` |
| Места менеджеров: сколько, формат | `sales.managers`, `sales.format` (`open` = «открытые столы») |
| Переговорная: сколько, на сколько человек | `meet: {n, seats}` (не отмечено «на сколько» → 6) |
| Сделочная / VIP | `vip` |
| Банк / касса; банков | `bank` (+ `cashier: true`, если явно касса) |
| Кабинет РОП | `director: "room"`; «место в бэк-офисе» → `"backoffice"` |
| Бэк-офис: сотрудников | `backoffice` («2–3 чел» → 3, берите верхнюю границу) |
| Ресепшен: стойка на N чел. | `reception` |
| Зона ожидания: мест | `waiting` («10–12» → 12, «15+» → 16) |
| Бар / кофе | `cafe`: отмечена «барная стойка с бариста» → `bar`, иначе `corner` |
| Детская | `kids`: «уголок в зале» → `corner`, «отдельная комната» → `room` |
| Макет: размер стола / только экран | `maket` |
| Медиа / VR | `media` |
| Шоурум | `showroom`; «мокап квартиры» → `mockup`; «если останется» → ключ в `optional` |
| Гардероб | `wardrobe` |
| Санузел для гостей | `wc_guest`: «М + Ж + МГН» → `mf` |
| Кухня персонала: обедают N; мини / со столом | `kitchen: {seats, type}` |
| Санузел персонала | `wc_staff` (нет → 0) |
| Архив / склад | `archive` (+ `storage`, если отдельно «рекламные материалы» и площадь ≥ 400) |
| Пост охраны | `security` |
| Технические помещения «заложить» | ничего: они закладываются всегда |
| Пожелания | `notes` |

## 3. Спорные случаи

- **РОП в числе менеджеров.** «5 МПП + 1 РОП» — это `managers: 5` и `director: "room"`. РОП не кладётся в число мест продаж.
- **«Сделочная / РОП комната — нет», а кабинет РОП — да.** Значит, сделочной нет (`vip: 0`), а кабинет РОП есть.
- **Диапазон высоты «6–7 м».** Берите 6,5 м: антресоль тогда проходит (3,3 + 0,3 + ≥ 2,2 м).
- **«20 % на второй уровень».** Это `upper: "auto"` при h ≥ 6,2 м: движок сам поднимает на антресоль РОП, бэк-офис, кухню, архив и серверную. Отчёт покажет фактическую долю.
- **Помещения нет в таблице** (VR-комната, шоурум кухни, комната матери и ребёнка). Ближайший ключ с пометкой в `notes` — или добавьте его в план после сборки (MCP `add_room` или `KB.apply(S, {op: "add_room", …})`).
- **Противоречие в ТЗ** (например, 12 МПП в 150 м²). Всё равно соберите план: движок уберёт лишнее и напишет, что именно. Потом предложите заказчику выбор: больше площади или меньше мест.
