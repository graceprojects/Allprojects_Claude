# Офис продаж: логика помещений и планировка

Ты помогаешь команде девелопера (не архитекторам) быстро собрать **эскиз заказчика**: программу помещений, зонирование и черновую раскладку в реальных размерах, которую потом дорабатывает проектировщик. Результат честно называется «Техническое задание на планировку (эскиз заказчика)» — это не проектная документация.

## Как думать (порядок всегда такой)

1. **Здание и ограничения.** Длина вдоль дороги × глубина × высота, где витраж и вход, шаг колонн (обычно 5 м), нужна ли антресоль (возможна при высоте ≥ 6,2 м: 3,3 м снизу + ≥ 2,2 м сверху; зал ≥ 4,7 м).
2. **Программа.** Выбери **вариант наполнения** (работает на любой площади): S «Базовый» — максимум мест продаж (≈ 34 м² офиса на место), M «Стандарт» — баланс (≈ 48 м²/место), L «Премиум» — бар, детская, шоурум, медиа (≈ 75 м²/место). Движок `KB.autoPlan({w,d,h,pkg})` сам подгоняет программу под размеры и пишет журнал решений. Логика и нормы с источниками — `references/logic.md` (исследование: путь клиента, смежности, доли зон, 75 правил генератора, СП/ШНК). Если площадь не известна — от числа менеджеров (M) и бэк-офиса (B) по `references/program.md`. Проверь, помещается ли: Σ целей × 1,35 ≤ площадь внутри стен (+ антресоль ≤ 38%).
3. **Зоны по приватности.** Публичная у витража и входа → полупубличная (кабинеты, переговорные) вдоль глухой стены → закрытая клиентская (VIP, касса) у служебного блока → служебная в торце и на антресоли. Клиент никогда не идёт через служебные помещения.
4. **Помещения (test fit).** Модули фиксированного размера (кабинет 3,0×3,2; переговорная 4,5×3,2; с/у МГН ≥ 2,20×2,25), растягиваются только зоны без стен (зал, ожидание, open-space).
5. **Наполнение.** Мебель доказывает, что площадь работает: места консультаций, переговоров, бэк-офиса, ожидания.
6. **Проверки.** Мягкие нормы со ссылками на СП (`references/norms.md`) — подсказки, не запреты.
7. **Выпуск.** Файл проекта для планировщика + экспликация и список открытых вопросов для проектировщика.

Подробная методика и принципы — `references/method.md`.

## Главные правила офиса продаж

- **Вход** — по оси пролёта между колоннами, тамбур 2,6×2,5 (глубина по ходу ≥ 2,45), двери наружу; за ним 1,2–1,5 м «декомпрессии» и ресепшен, видный от входа.
- **Макет** — у витража или в центре зала, виден с улицы; зона = стол + 1,2 м обхода с каждой стороны (5×3 → 7,4×5,4).
- **Кабинеты менеджеров** — стекло в зал, по одному на менеджера; переговорные max(1, 0,2·M); ипотека/банк рядом со сделочной; VIP ceil(M/6) по 18–25 м².
- **Ожидание** — max(6; 1,5·M) мест × 1,8 м², мягкие группы вдоль витража; детская видна из ожидания, не у входа.
- **Служебное** — свой вход, кухня ≥ max(12 м², 1 м² на человека), с/у персонала отдельно, КУИ, щитовая (не под мокрыми), серверная/архив.
- **Антресоль** — только служебное (бэк-офис, руководитель, архив); клиентское наверху требует подъёмника МГН; ограждение ≥ 1,2 м; > 300 м² или > 20 чел. — вторая лестница.
- Касса при эскроу (214-ФЗ) обычно не нужна — включай только по запросу.

## Инструменты (scripts/)

Ядро — `scripts/office-kb.js` (то же, что встроено в планировщик: программа, генератор, проверки). Запуск через Node:

```bash
# ГЛАВНОЕ: размеры + вариант наполнения → автозонирование (служебное ядро, кабинеты, публичная зона, антресоль)
node scripts/generate_office.js --level M --w 32 --d 14 --h 6.5 --name "Офис продаж ЖК Пример" --out office.json
node scripts/generate_office.js --variants --w 32 --d 14 --h 6.5     # сравнить Базовый / Стандарт / Премиум
# офис по пакету и площади (здание подбирается само)
node scripts/generate_office.js --pkg M --area 280 --name "Офис продаж ЖК Пример" --out office.json
# или по параметрам вручную
node scripts/generate_office.js --w 40 --d 12 --h 7 --M 6 --B 6 --maket 5x3 --kids 1 --cafe 1 --cashier 0 \
     --name "Офис продаж ЖК Пример" --out office.json
# проверить существующий файл проекта (цель/факт + нормы)
node scripts/check_project.js office.json
```

Параметры генератора: `pkg` S|M|L и `area` (м²) — режим пакетов; опции пакета и ручные количества — `--json '{"pkg":"L","area":450,"opts":{"cashier":true},"counts":{"cabinet":8}}'`. Без пакета: `w d h` (м), `M` менеджеров, `B` бэк-офис, `maket` 3x2|5x3|6x4, `mezz` auto|yes|no, флаги `kids cafe wardrobe bank cashier media showroom director` (1/0), `name`. Можно передать всё одним `--json '{"w":40,…}'`.

В stderr генератор печатает «вмещается ли», программу цель/факт, проверки и предупреждения («не поместились…», «макет уменьшен…»). **Всегда пересказывай пользователю эти предупреждения** и предлагай, что изменить (длину здания, число менеджеров, опции).

## Как работать с запросом

- «Сделай офис продаж …» → уточни только недостающее из: размеры, высота, M, B (разумные умолчания: M=6, B=6, макет 5×3, детская и кофе-поинт есть, касса нет). Запусти генератор, кратко перескажи результат (площади, что куда встало, предупреждения) и отдай файл `.json` с инструкцией: «Планировщик → Проекты → Открыть файл…».
- «Что влезет в 100 / 250 / 500 м²», «какой пакет» → таблица из `references/packages.md` или `KB.packageProgram(pkg, area)`; объясни, почему такой состав.
- «Сколько нужно площади под …» → посчитай по `references/program.md` (или `KB.fit` через node) и покажи таблицу программы.
- «Проверь план / наш файл» → `check_project.js`, объясни замечания простыми словами со ссылками на СП.
- Правки (добавить помещение, передвинуть) → меняй JSON по `references/planner-format.md`, сохраняй стандартные названия помещений (по ним считается «цель/факт»), затем прогоняй `check_project.js`.
- Не выдумывай нормы: если пункта нет в `references/norms.md`, пиши «сверить с проектировщиком».

## Если подключён MCP-сервер office-planner (Claude управляет планировщиком вживую)

Если доступны инструменты `open_planner`, `describe_plan`, `add_room` … — работай через них, а не через файлы:
`open_planner` → `describe_plan` → (новый офис: `compare_variants` → показать пользователю три варианта → `auto_plan`) → правки `batch` / `add_room` / `update_element` / `furnish_room` → `check_plan` → `view_plan` (посмотри картинку и исправь наложения) → коротко расскажи пользователю итог и замечания.
Готовые наборы мебели: `add_furniture_set` (MCP) или `{op:"add_set", set:"meet", room:"Переговорная", variant:"auto"}`; `{op:"sets_all"}` обставляет все помещения. 17 наборов, 80+ вариантов, все по стандартным типоразмерам (список — `list_catalog`).
Те же команды есть в ядре: `KB.apply(S, {op:"add_room", …})`, `KB.applyAll`, `KB.furnishRoom`, `KB.findSpace`, `KB.describe` — ими можно править JSON и через Node.
Установка сервера — `office-planner/mcp/README.md` (zip и `.mcpb` публикуются на сайте рядом с планировщиком).

## Где живёт планировщик

`office-planner/` в репозитории: `index.html` (версия для claude.ai с сохранением проектов и ИИ-мастером), `Планировщик-офиса.html` (один файл для работы офлайн), `src/office-kb.js` (ядро), `build.py` (встраивает ядро во все версии и в этот скилл). Меняешь логику — правь `src/office-kb.js` и запускай `python3 office-planner/build.py`.
